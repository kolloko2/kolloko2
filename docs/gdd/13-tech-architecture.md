# 13. Техническая архитектура

## 13.1 Стек

| Слой | Технология | Обоснование |
|---|---|---|
| Язык | **TypeScript** (клиент и сервер) | Общий код симуляции и типов данных |
| Рендер | **Three.js** (WebGL2, опционально WebGPU) | Требование; зрелая экосистема |
| UI | **React 18** + Zustand (состояние) + Tailwind/CSS-модули; графики — **uPlot**/ECharts; граф цепочек — React Flow | Быстрая разработка сложных панелей |
| Сборка | **Vite** | Быстрый dev-сервер, code splitting |
| Симуляция | Чистый TS-модуль `@game/sim` (без зависимостей от DOM), запускается на сервере (Node.js) и в Web Worker (соло-офлайн) | Один код для всех режимов |
| Сетевой сервер | **Node.js** + **Colyseus** (комнаты, state sync) или собственный WebSocket-сервер на `uWebSockets.js` | Готовая модель комнат/лобби |
| Транспорт | WebSocket (основной), бинарная сериализация (**MessagePack** или FlatBuffers) | Низкий трафик |
| Голос (опц.) | WebRTC (через SFU, например LiveKit) | P2P-нагрузка на клиентов мала |
| БД | **PostgreSQL** (аккаунты, профили, сохранения-метаданные, рейтинги, контракты-история), **Redis** (сессии, матчмейкинг, pub/sub) | Стандарт |
| Хранилище сохранений | Объектное хранилище (S3-совместимое), снапшоты сжатые zstd | Большие бинарные снапшоты |
| Аутентификация | OAuth (Google, Discord, Steam — при выходе на Steam), гостевой вход | Быстрый старт |
| Инфраструктура | Docker, Kubernetes (или Fly.io/Hetzner для старта), CDN для ассетов | Масштабирование комнат |
| Мониторинг | Prometheus + Grafana, Sentry (клиент/сервер) | |
| Тесты | Vitest (юнит), Playwright (e2e), **детерминированные тесты симуляции** (golden snapshots) | |
| Десктоп (post-launch) | Electron/Tauri-обёртка для Steam | Тот же код |

## 13.3 Модель симуляции

### 13.3.1 Авторитетный сервер + команды
- Клиент **не** симулирует мир в мультиплеере — только отображает. Все действия — **команды** (`OpenBusiness`, `SetPrice`, `PlaceOrder`, `ProposeDeal`, …), отправляемые на сервер.
- Сервер валидирует (права, деньги, правила), применяет на ближайшем тике, рассылает результат.
- Оптимистичный UI для мгновенного отклика (например, цена меняется в UI сразу; откат при отказе).

### 13.3.2 Детерминизм
- Симуляция детерминирована при одинаковом сиде и последовательности команд (фиксированный порядок обработки, собственный PRNG — например, xoshiro128**, без `Math.random`, аккуратная работа с float: денежные суммы — **целые центы в `bigint`/int64** или фиксированная точка).
- Позволяет: реплеи (сид + лог команд), отладку десинхронизаций, тесты-«золотые снапшоты», соло-оффлайн с тем же кодом.

### 13.3.3 ECS-подобная структура данных
- Сущности: `Company`, `BusinessUnit`, `Lot`, `City`, `Country`, `Market`, `Contract`, `Shipment`, `Person`, `Brand`, `Technology`, `Event`.
- Хранение в **структурах массивов (SoA)** / TypedArrays для горячих данных (запасы, производство, потоки) — кэш-дружественно и быстро сериализуется.
- Системы, выполняемые по расписанию:

| Система | Частота |
|---|---|
| CustomerFlowSystem | Каждый тик (час) |
| ProductionSystem | Каждый тик |
| LogisticsSystem (движение грузов) | Каждый тик |
| InventorySystem (порча, приём) | Каждый тик |
| SpotMarketClearingSystem | Ежедневно |
| ContractExecutionSystem | Ежедневно |
| FinanceSystem (платежи, проценты) | Ежедневно |
| LaborMarketSystem | Еженедельно |
| AIStrategySystem | Ежедневно (тактика) / ежемесячно (стратегия), с распределением по тикам |
| AccountingSystem (P&L, отчёты) | Ежемесячно |
| MacroSystem (ВВП, инфляция, курсы, ЦБ) | Ежемесячно |
| StockMarketSystem | Ежедневно (игровой день — торговая сессия) |
| PoliticsSystem | Ежемесячно |
| EventDirector | Ежедневно (проверка триггеров) |
| DemographySystem | Ежеквартально |

### 13.3.4 Производительность сервера
- Целевая нагрузка: 1 комната (8 игроков, 200 ИИ, ~50K юнитов) ≤ 15% одного ядра на скорости ×4.
- Тяжёлые системы (ИИ, клиринг) распределяются по тикам (amortization) и/или выносятся в `worker_threads`.
- Профилирование с первого прототипа; бюджет на систему.

## 13.4 Сетевой протокол

### 13.4.1 Синхронизация состояния
- **Interest management:** клиент подписывается на «области интереса» (текущий видимый город/район, свои компании, открытые панели). Сервер шлёт только релевантное.
- **Слои данных:**
  - *Глобальный* (всем, 1 раз в игровой день): цены рынков, макро, индексы, новости.
  - *Приватный* (владельцу): полные данные его компаний.
  - *Видимый* (по туману войны): публичные данные соперников.
  - *Локальный* (по подписке на город/район): бизнесы на карте, потоки для визуализации.
- **Дельты** + периодические полные снапшоты; номер версии для каждой подписки.
- Целевой трафик: < 20 КБ/с на клиента в активной фазе.

### 13.4.2 Команды
```ts
type Command =
  | { t: 'OpenBusiness'; lotId: LotId; type: BusinessType; config: BizConfig }
  | { t: 'SetPrice'; unitIds: UnitId[]; product: GoodId; price: Money | PricePolicy }
  | { t: 'SetProcurement'; unitId: UnitId; good: GoodId; policy: ProcurementPolicy }
  | { t: 'Hire'; unitId: UnitId; role: RoleId; count: number }
  | { t: 'PlaceMarketOrder'; market: MarketId; side: 'buy'|'sell'; qty: number; limit?: Money }
  | { t: 'ProposeDeal'; to: PlayerId|AiId; offer: DealTerms }
  | { t: 'RespondDeal'; dealId: DealId; action: 'accept'|'reject'|'counter'; counter?: DealTerms }
  | { t: 'StockOrder'; ticker: Ticker; side: 'buy'|'sell'|'short'; qty: number; limit?: Money }
  | { t: 'StartResearch'; techId: TechId; centerId: UnitId }
  | { t: 'Lobby'; country: CountryId; lawId: LawId; stance: 'for'|'against'; points: number }
  | ...;
```
- Каждая команда имеет `seq` клиента для идемпотентности и подтверждения.
- Rate limiting на сервере.

## 13.5 Античит и безопасность
- Серверная авторитетность: клиент не может «нарисовать» себе денег.
- Туман войны соблюдается на сервере (клиенту не отправляются скрытые данные — нельзя «подсмотреть» в devtools).
- Валидация всех команд; лимиты частоты; анти-бот эвристики в рейтинговых режимах.
- **Сговор/фарминг рейтинга** (передача денег от твинка) — детекция аномальных сделок в рейтинговых режимах; ограничение безвозмездных переводов в рейтинге.
- Защита аккаунтов: OAuth, CSRF/CORS, TLS.

## 13.6 Сохранения
- **Соло:** локально в IndexedDB (снапшот zstd + лог команд с последнего снапшота) + облачная синхронизация для залогиненных.
- **Мультиплеер:** снапшоты на сервере каждые 5 реальных минут и при выходе всех игроков; ротация (последние 10).
- **Версионирование формата** и миграции (схема данных с версией; миграционные функции).
- Реплеи: сид + лог команд → воспроизведение (полезно для стримеров и разборов багов).

## 13.7 Данные игры (data-driven)
- Все товары, рецепты, бизнесы, технологии, события, страны, города — во внешних **JSON/YAML** файлах с JSON-схемами (валидация в CI).
- Горячая перезагрузка данных в dev-режиме для балансировки без перекомпиляции.
- Балансные таблицы ведутся в Google Sheets/Excel → экспорт скриптом в JSON.
- **Моддинг** (post-launch): загрузка пользовательских пакетов данных (новые товары/бизнесы/сценарии) в приватных лобби.

## 13.8 Структура репозитория (монорепо)


## 13.9 Инструменты разработки
- **Headless-симулятор:** прогон 50 игровых лет без рендера с ИИ-ботами за минуты → графики экономики для балансировки (стабильность цен, инфляции, отсутствие «вечных двигателей»).
- **Экономические инварианты в CI:** сумма денег в системе = эмиссия ЦБ + внешний мир; отсутствие отрицательных запасов; цены в разумных границах.
- **Редактор карты/данных** (внутренний веб-инструмент).
- **Debug overlay** в клиенте: FPS, draw calls, сетевой трафик, состояние подписок, быстрые читы для тестов (в dev-сборке).
